# Секретные чаты

Секретный чат — отдельная переписка между конкретными `user_id/device_id` двух пользователей. Для API нужен действующий сеанс, привязанный через доказательство владения Signal identity key. Создание нового устройства, вход по QR, резервная копия или обычная синхронизация не переносят секретные ключи и историю.

## Создание и открытие в браузере и Android

Откройте настройки аккаунта → «Секретные чаты». Введите имя пользователя (можно с `@`), нажмите «Найти собеседника», выберите найденного человека и затем одно из доступных устройств. Устройство нужно выбрать явно, даже если найдено только одно. Список поступает из аутентифицированного `/e2e/devices/:userId`: произвольное устройство ввести нельзя. Этот endpoint требует общего обычного чата; если устройств нет, сначала откройте обычную переписку и попросите собеседника войти на своём устройстве. Если сервер прислал название или платформу устройства, интерфейс показывает их; иначе показывает номер устройства в списке и окончание его идентификатора для различения. Платформа по идентификатору не угадывается.

Выберите срок сообщения от 30 до 86400 секунд и создайте чат. Обменяйтесь показанными публичными ключами, вычислите код безопасности, сравните его вне этого чата и подтвердите совпадение. До подтверждения отправка остаётся заблокированной. Поиск человека и выбор устройства не заменяют эту проверку.

Сохранённые чаты открываются из списка с именем собеседника, устройством и датой создания, если эти сведения доступны. Если профиль больше недоступен, используется подпись «Собеседник»; внутренний ID чата вводить не нужно. Изменение поискового запроса, уход в фон и смена аккаунта сбрасывают выбор; запоздалый ответ не восстанавливает его.

## Локальная история и срок хранения

`web/secret-vault.js` хранит `secret-vault:v1` только через существующее зашифрованное хранилище аккаунта: AES-GCM/IndexedDB в браузере и SQLCipher/устройственный ключ в SecureStore на Android. Запись содержит private X25519 key, согласованный peer key, подтверждение отпечатка, replay fence и историю. Этот namespace не входит в экспорт Signal/групповых ключей. Нельзя включать vault в резервные копии или серверную синхронизацию.

У каждого сообщения собственное `expires_at` (30–86400 секунд); история очищается по таймеру. Ключ и replay state удаляются после TTL неактивности: создание/подтверждение ключа или отправка/получение сообщения продлевают этот срок. Простой просмотр и polling срок не продлевают. Активный экран удаляет истёкшее состояние; запуск аккаунта и повторное открытие также выполняют очистку. Пока процесс остановлен, код очистки не выполняется: физическое удаление записи происходит при следующем запуске, но истёкшая история не показывается и не может возобновить сеанс. Хранилище ограничено 100 чатами на аккаунт и 1024 сообщениями в одном чате; replay fence также ограничен 1024 входящими nonce.

Уход в фон и закрытие экрана очищают plaintext draft, историю из UI, ввод peer key/verification и ключи активного crypto object. Неистёкшая зашифрованная запись остаётся на том же устройстве и позволяет продолжить ту же пару после перезапуска процесса. Explicit logout и удаление аккаунта очищают vault. Переключение между сохранёнными аккаунтами только закрывает экран; оно не переносит историю между аккаунтами.

Открытие сохранённого чата требует соединения: до показа локальной истории клиент проверяет exact device и доступ к mailbox. Это намеренное ограничение: офлайн нельзя проверить удаление чата на другом устройстве. На активном экране проверка повторяется примерно раз в пять секунд; наблюдённое удаление уничтожает локальную запись. Сетевая задержка влияет на скорость обнаружения удаления. Недоступность сети не раскрывает локальную историю при новом открытии.

## Протокол и доставка

Используется существующий протокол v1: X25519, HKDF-SHA256 (`chat_id` salt, `67chat-secret-v1` info), AES-256-GCM с `chat_id` в AAD и случайным nonce. Шифруются текст, `device_id` отправителя и срок жизни. Получатель проверяет user/device binding, срок, повтор nonce и вручную сравниваемый fingerprint обоих публичных ключей и `chat_id`. Перед отправкой обе стороны должны сверить fingerprint по независимому каналу.

API хранит только ограниченную очередь ciphertext — максимум 100 envelopes по 64 КБ, до TTL. Получатель сначала сохраняет историю и replay state в зашифрованный local store, затем отправляет ACK, удаляющий серверный ciphertext. Повтор получения после сбоя ACK не создаёт дубликат в истории. Аутентифицированное уже истёкшее сообщение удаляется без показа и не блокирует более новые сообщения.

Это **не полный Signal Double Ratchet**. Внутри чата нет нового ключа для каждого сообщения, per-message forward secrecy или post-compromise recovery. Компрометация действующего secret key раскрывает доступный ciphertext этого чата. Локальное шифрование защищает записи в хранилище; оно не защищает от кода, выполняющегося внутри разблокированного приложения/страницы. Удаление в JavaScript означает прекращение доступа и удаление записей; гарантировать физическое стирание копий из flash/резервных копий ОС невозможно.

## Защита экрана

Android вызывает установленный Expo ScreenCapture `preventScreenCaptureAsync('67chat-secret')` до открытия истории и снимает защиту после закрытия/очистки. Проверка реальной блокировки screenshots, recording и recent-app previews требует физического устройства с новой APK.

Браузер не может запретить снимки и запись экрана; интерфейс прямо сообщает об этом. При `visibilitychange` в hidden очищаются открытая история и все поля секретного экрана. Экспорт/пересылка секретной истории не предоставляются.
