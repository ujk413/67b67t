# Проверка изменений перед объединением

Основной репозиторий — `ujk413/67b67t`, основная ветка — `main`.
Изменения отправляются отдельной веткой `codex/*` и Pull Request: так видны
исходный код, diff, замечания и результаты CI. Объединение PR запускает Android
workflow, который публикует APK на сервер; до объединения проверить versionCode.

В PR автоматически выполняются Messenger checks и Repository safety:

- TypeScript и мобильные/API/web-тесты;
- запрет отслеживаемых ключей, окружения, баз, медиа, архивов и сборок;
- Gitleaks по истории с редактированием секретов в диагностике. Узкие исключения
  в `.gitleaks.toml` относятся только к проверенным публичным/служебным значениям.

Локально из корня репозитория:

```powershell
npm run typecheck --prefix mobile
npm test --prefix mobile
npm test --prefix api
python tests/repository_safety_test.py
python scripts/check_tracked_files.py
```

Для ревью через Codex открыть этот GitHub PR в разделе «Проверка кода».
Наличие PR и зелёных тестов помогает проверке, но не гарантирует отсутствие багов.
В описании PR нужно различать проверки на устройстве, в браузере и автоматические.

Особое внимание для мессенджера: сохранение аккаунтов и очереди при обновлении;
отмена после каждого асинхронного шага; изоляция аккаунтов; скрытые сообщения
после редактирования/переподключения/поиска; права участников; одинаковая схема
для новой и существующей БД; светлая и тёмная темы.

`.env`, Firebase credentials, keystore, `data/`, `uploads/`, `builds/` и локальные
архивы остаются на машине/сервере. Доступ CI к ключам предоставляется через
GitHub Actions Secrets. Не прикладывать приватные логи или реальные переписки к PR.
