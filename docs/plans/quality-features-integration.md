# Stage 8: качество и настройки

## Реализовано

- Настройки на уровне аккаунта в `quality_preferences`: RU/EN для интерфейсов сайта и Android, тихие часы с IANA timezone, группировка уведомлений, автозагрузка по типу и сети, лимит кеша, обои и цвет, согласие на crash reports. `api/quality-features.sql` идемпотентен и применяется установщиком API на старой базе; fresh schema синхронизируется в `db/init.sql`.
- `GET /quality/capabilities`, `GET/PUT /me/quality`, `POST /me/crash-reports`. Сервер принимает только известные коды ошибки, подсистему, платформу, версию и время. Текст сообщений, идентификаторы сессий, ключи, токены, стеки и произвольные строки не принимаются. Отчёт можно предварительно просмотреть; отправка только после согласия и отдельного нажатия.
- Серверная и браузерная доставка подавляет сообщения в тихие часы, но проверочные уведомления и звонки сохраняются. Android-клиент дополнительно скрывает foreground-баннер. Группировка следует настройке.
- Новый Android APK регистрирует `quick_reply=true` на устройстве. Только таким устройствам API шлёт data-only FCM; `CallMessagingService` создаёт системное уведомление с настоящим `RemoteInput`, не показывая текст на экране блокировки. Ответ возвращается в JS, проверяет текущий аккаунт и доступ к комнате и попадает в существующую очередь E2E. Старые APK получают прежний notification payload.
- Web: «Настройки → Качество, язык и оформление»; Android: тот же пункт в настройках. Обои и цвет применяются к чату; экран показывает светлый и тёмный предпросмотр. Клиенты сохраняют параметры на сервере. Android сохраняет локальную политику под ID аккаунта. Если сеть не определяется, автозагрузка закрыта по умолчанию; ручное открытие доступно.
- Веб-кнопка очистки удаляет CacheStorage; мобильная — локальные расшифрованные/загруженные медиа. Секреты сообщений и сеансов в crash report не попадают.

## Выпуск и проверка

API-миграция `push_devices.quick_reply` должна попасть и в `db/init.sql`. Сначала выпустить сервер с поддержкой старых APK, потом web и новый APK. Проверить `node --test tests/quality-features.test.mjs tests/quality-policy.test.mjs tests/native-push.test.mjs tests/mobile-push.test.mjs tests/web-push.test.mjs tests/web-notifications.test.mjs tests/i18n.test.mjs tests/browser-feature-scope.test.mjs` и `cd mobile && npm run typecheck`. На текущем checkpoint Kotlin-компиляция RoomKey и ExpressiveIntegration прошла; ответ из заблокированного Android и визуальная проверка обеих локалей всё ещё требуют реального APK.

## Известные пределы

- RU/EN подключён к общим экранам сайта и Android, меню, настройкам, авторизации, работе с медиа и датам. Язык применяется реактивно через ThemeProvider и перерисовку веб-оболочки; динамические сообщения, имена и подписи пользователей не переводятся. Полный визуальный обход обеих локалей на устройстве остаётся обязательным перед выпуском.
- Выбранный язык сохраняется нативными модулями для фоновых уведомлений сообщений и звонков, подписей аудиовыходов и Android-виджета. Статические ярлыки launcher и подписи, которые формирует сама ОС (например системная установка и CallStyle), следуют языку Android; ресурсы ярлыков содержат RU и EN. Изменение app locale с пересозданием Activity и миграция закреплённых ярлыков здесь не выполняются.
- Веб-клиент применяет правило автозагрузки только если браузер сообщает тип соединения Wi-Fi/cellular. При отсутствии Network Information API загрузка остаётся ручной.
- Клиентский автозапуск crash reports не включён; это явная отправка очищенного отчёта пользователем. Сбор без согласия отсутствует.
- Большая история/списки и N+1 реакций оптимизируются в других этапах. Производительность на 1000 комнатах/10000 сообщениях и Android lockscreen quick reply требуют физической проверки.

## Исправления независимого ревью

- Android уведомления используют отдельные PendingIntent для открытия и ответа, привязанные к аккаунту и комнате через action/data URI. Обычное нажатие передаётся отдельным native event. При несовпадении аккаунта показывается явное подтверждение переключения; поздняя ошибка ответа после выхода не восстанавливает старую отправку.
- В режиме прокси/Tor клиент не запрашивает токен FCM и не регистрирует push. Перед сменой транспорта строгая отмена регистрации должна успешно завершиться; обычный выход сохраняет прежнее поведение.
- Очистка веб-медиа не удаляет CacheStorage оболочки и не ломает офлайн-запуск. При интеграции вызывается также очистка ограниченного кеша расшифрованных URL.
- `:67chat-room-key:compileDebugKotlin` прошёл после изменений уведомлений. Реальные RemoteInput, lockscreen и переход между аккаунтами всё ещё требуют проверки новой APK на устройстве.

## Локализация интерфейса

`web/i18n.js` и `web/i18n-en.js` — общий каталог исходных русских UI-ключей и английских переводов. `t(source, ...parameters)` принимает статический ключ; имена, сообщения, usernames и подписи передаются отдельными параметрами и не переводятся. `locale()` задаёт язык форматирования дат. Константные таблицы содержат исходные ключи и переводятся при чтении, чтобы язык не фиксировался до загрузки настроек.

`scripts/i18n_static_copy.cjs` — инструмент миграции выбранных UI-файлов, а не часть runtime. Он оборачивает только проверенные ключи каталога и статические HTML/JSX-подписи. Имена полей, режимы протокола, шифртексты и конструкторы Error сохраняются; перевод ошибок выполняет presentation helper `userError`, после программной обработки retry/security. Не применять инструмент к API, криптопротоколу или данным сообщений.

Проверка: `node --test tests/i18n.test.mjs` использует настоящий каталог, реальные native formatters и HTML веб-авторизации. Проверяются русские имена и тексты в английском интерфейсе, EN/RU даты, plural, переключение языка и скрытие неизвестных технических ошибок.
