# Stage 7 integration contract

The expressive protocol is an encoded `text` value (`[67chat:v1]` + validated JSON). It must traverse the existing `sendMessage` / outbox encryption path. Never copy poll contents, quiz answers, or coordinates into `meta`, notifications, API catalog tables, or the room preview. Parse only after the normal recipient or group sender-key decrypt path has completed.

## API entrypoint (`api/server.js`)

Import `installExpressiveFeatures` from `./expressive-features.js` and call it after the ordinary room/member/auth helpers exist. Pass `{pool,requireAuth,isRoomMember,getRoomRole,broadcastToRoom}`. It runs the idempotent `api/expressive-features.sql` migration. Put the same schema into `db/init.sql` for fresh volumes. `api/expressive-features.sql` is not a replacement for existing migrations.

Use the returned functions in the existing message routes:

1. After membership and before inserting a plaintext text message, `await expressive.validatePlaintext({roomId,userId,text,encrypted:false})`. For an encrypted envelope, use `encrypted:true` and leave the ciphertext opaque. Do not reject ordinary plaintext messages.
2. Inside the **same** send transaction after `INSERT ... RETURNING id`, `await expressive.bindDice({roomId,userId,messageId,text,query:client.query.bind(client)})`. Reject on failure and roll back so a server die cannot be reused or attached to another message.
3. Before text edit, require `expressive.canEditText(oldText)` and `expressive.canEditText(newText)`. This protects dice, votes, poll creation/close and location events from mutation.
4. In `/media/:id` and `/media/:id/thumb` access control, allow `await expressive.canReadCatalogMedia(mediaId,me.id)` after the existing authorized media paths. This grants public or owned catalog media only; private packs stay private.

Catalog image requests use the existing authenticated media route. Both clients upload catalog files through authenticated `/media/upload` and then add the returned media ID to a pack. The server must pass a self-hosted GeoJSON `mapGeoJSON` object to `installExpressiveFeatures`; map geometry is served only through `/expressive/map-bundle` to authenticated clients. Without this bundle the UI says the local map is unavailable.

## Web entrypoint (`web/app.js`, `web/index.html`, `web/sw.js`)

`web/expressive-features.js` exports `openExpressiveFeature(mode,context)`, `renderExpressiveMessage(message,events,context)`, and `stopExpressiveLiveLocations(userId)`. Import from the app module. The opener accepts modes `emoji`, `stickers`, `poll`, `dice`, `contact`, `location`, `export`. Supply `{request,me,room,rooms,openRoom,enqueue,refresh,local,decode,report}`. `request(path,{method,body})` must pass JSON or multipart `FormData` through the existing authenticated API wrapper. `enqueue(roomId,text)` must use the standard text send path including E2E encryption; it must not POST raw text independently. `decode(message)` must mark `_decrypted` only when actual decryption succeeded. `local.insertEmoji` may insert into the current composer; otherwise the dialog sends the emoji as a message. Quiz answer/salt is stored locally under the account and poll IDs so the author can reveal it on close; delete this local state on logout/account deletion. Call `stopExpressiveLiveLocations(userId)` on account switch/logout.

After decryption, call `parseMessagePayload(message.text)`. Hide `isExpressiveControl(payload)` messages from ordinary bubbles but keep them in the room event list passed to `renderExpressiveMessage`. The renderer returns a DOM node for non-control payloads. Prevent typed messages from being edited except the server-approved mutable kinds. Use `expressiveSummary(payload)` for previews only **after decryption**, never in server push payloads. Include both `web/expressive-features.js` and `web/expressive-payloads.js` in the service-worker cache, bump shell `?v=` strings and `CACHE_NAME` together.

The web dialog uses browser geolocation. While the page remains visible, a browser position watch sends encrypted location updates; it stops on expiry, page hide, explicit stop, or account cleanup. The message map draws the server's GeoJSON bundle locally in SVG, with no third-party map request. The bundle must be supplied from OSM-derived data by the deployment.

## Mobile entrypoint (`mobile/App.tsx`, `mobile/src/screens/ChatScreen.tsx`)

`ExpressiveFeatures({mode,context})` uses the common `FeatureContext` and `onSend` standard encrypted text path. Mount it with modes above. Pass already decrypted messages plus all decrypted room events to `ExpressiveMessage({message,events,context})` and suppress `isExpressiveControl` bubbles. The quiz answer/salt is stored in the encrypted account repository. The sender can reveal it when closing from the same device. SDK55 `expo-location` is installed; configure foreground location permission and call `stopExpressiveLiveLocations(userId)` (mobile export) on account switch/logout. The mobile foreground watcher sends encrypted updates and stops on background, expiry, or explicit stop. The map draws the self-hosted GeoJSON bundle locally using `react-native-svg`.

`ShareInConfirm({context,onShareFile})` should mount above the authenticated workspace. It reads pending Android share content from the native module and displays the current account, preview, and selectable chats. It sends only on explicit confirmation. `onShareFile(roomId,uri,mime)` must import content URIs into app cache and route through `protectedUploader` plus the existing attachment message flow; without that callback it refuses attachments. Account switching should dismiss this overlay and present it under the selected account. No share data is saved in the widget, shortcut, or lock-screen notification.

Add `./plugins/withExpressiveAndroid` to `mobile/app.config.js` plugins. The local Expo module under `mobile/modules/expressive-integration` provides the encrypted durable Android share bridge and a widget that says only “67chat / Открыть чаты”. Expo autolinking already detects the module. The plugin adds SEND/SEND_MULTIPLE filters and a launcher shortcut during prebuild. The APK must be rebuilt and delivered through the release pipeline; a server bundle cannot activate native integration.

## Known unfinished integration and verification

Modules are now wired into API, web and Android entrypoints in the working tree. This does not imply deployment or installation. Device validation of incoming share, widgets, notification body taps and RemoteInput remains required after an APK rebuild. Map data still needs a separately supplied self-hosted OSM-derived GeoJSON bundle.

Private catalog sends now copy the asset through the normal protected attachment queue. The original private catalog ID is never the recipient's media ID. `details.expressive` (kind and bounded label) travels inside the encrypted attachment key envelope. Transparent stickers and looping muted GIF/video use the decrypted attachment source. Public catalog access does not grant access to private packs.

`expressive_installed_packs` and `/expressive/installed` provide account-scoped installation/removal; existing pack selection, owned title/tags editing, explicit publication and deletion are exposed on both clients. Emoji categories combine with RU/EN search. Quiz answers use the encrypted account repository rather than unencrypted browser storage.

Android and web poll/location reducers now use the same authorized decrypted event materialization. The initial scan streams every history page once; normal receive and `/sync` deltas append or replace events and apply edit/delete/personal-hide tombstones. Native repository observers coalesce committed changes before updating the cache. Session cleanup and revoked rooms remove cached materializations. The LRU keeps six rooms, each with at most 20,000 event rows and approximately 16 MiB serialized UTF-16 data; overflow refuses incomplete results and requires explicit retry. Progress, cancellation, and retry preserve the full-history requirement before voting. Native displayed history is separately bounded to 300 messages; incoming updates preserve an older visible anchor, and explicit older/newer paging changes that window. The OSM overview rendering remains unchanged.

Client export traverses every authorized `/history` page and refuses failed decryption. Selected attachments are embedded as base64 in JSON or download links in HTML. Selection defaults to empty, includes an estimate, and is limited to 20 MiB original data to limit memory pressure. Executable inline media types are downgraded to `application/octet-stream`; names are escaped. Secret chats remain excluded. Streaming export is a future scalability improvement.

Incoming Android shares now commit their text/metadata preview to an AES-GCM journal using Android Keystore in `noBackupFilesDir` before opening external streams. Only external `content://` providers are accepted; file paths, own authorities, and providers resolved to the app package are rejected. Files are copied while the temporary grant lives into private storage: at most ten files, 100 MiB minus 16 bytes per file, 250 MiB per operation, four pending operations. Missing/revoked/incomplete/oversized files remain visibly unconfirmable. A new share queues behind the current preview. Restoring an unconfirmed preview never sends automatically. Explicit confirmation locks the original account/chat; every durable outbox registration advances an encrypted per-item journal, and retries reuse the same IDs. Cancel/finished/account removal removes source copies; unconfirmed imports expire after seven days, and interrupted pre-commit copies are cleaned on journal open. Confirmed incomplete operations remain available for explicit continuation or cancellation. The App adapter copies through a verified staging file into a deterministic queue-ID path before normal protected upload; process restart cannot create a second message from an already registered item.

Host-only performance evidence: run `node scripts/benchmark_expressive_history.mjs`. This exercises 1,000 actual web row render helpers, 10,000 event history records and poll reduction, incoming deltas, native client-ID deduplication and the 300-message window. It does not measure Android device scroll FPS, browser DOM layout, real decryption CPU, or network latency; those remain acceptance checks on a rebuilt APK/browser.

Review follow-up: an incoming message beyond a known `has_newer` gap updates the local event cache/unseen marker but never becomes the displayed `/history?after=` cursor. Only explicit newer paging extends that contiguous range. The active-window unseen ledger keeps at most 20,000 arrival IDs/minimal positions (no text), deduplicates received IDs/client IDs, ignores history-page additions, and consumes markers from actual viewability receipts; an overflow is shown with `+`. Destructive account cleanup now validates the owner UUID, enumerates only that exact draft directory without recursion, and deletes only the existing approved filename formats plus native share UUID/index `.shared` / `.shared.importing` names.
